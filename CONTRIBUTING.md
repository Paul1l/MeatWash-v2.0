# Совместная разработка

Репозиторий открыт для нескольких человек. Ниже — минимум, которого достаточно,
чтобы не мешать друг другу и не сломать опубликованный макет.

Опубликованный сайт: https://paul1l.github.io/MeatWash-v2.0/
Его собирает GitHub Actions из папки `dist` при каждом push в `main`. Всё, что
попало в `main`, через минуту видит клиент — поэтому напрямую в `main` не пушим.

## Доступ

Право на запись выдаёт владелец репозитория через Settings → Collaborators.
Если у вас есть доступ — работаете в этом же репозитории через ветки.
Если доступа нет — делаете форк и присылаете pull request из него.

## Первый запуск

```
git clone https://github.com/Paul1l/MeatWash-v2.0.git
cd MeatWash-v2.0
npm ci        # нужно только для проверок и пересборки, для просмотра не обязательно
npm start     # http://127.0.0.1:4173
```

Открывать `dist/index.html` через `file://` нельзя: браузер заблокирует модули.
Только локальный сервер.

## Ветки

Одна ветка — одна законченная правка. Называем по существу:

```
git switch -c cfg-mobile-panel
```

Префиксы не обязательны, но имя должно читаться без объяснений:
`cfg-mobile-panel`, `header-logo`, `fix-menu-scroll-lock`.

## Что проверить перед pull request

```
npm run check          # ресурсы, ссылки, якоря, цены, кадры витрины, ссылки записи
```

Проверка автоматически идёт на каждый pull request, но быстрее узнать
о проблеме у себя, чем через пять минут в Actions.

Руками, во всех случаях:

- 390, 768 и 1440 — горизонтальной прокрутки нет;
- в консоли браузера нет ошибок;
- на живых сайтах клиента ничего не менялось.

## Первый экран — фото-витрина

Первый экран — фото-витрина (`dist/js/stage.js`, кадры в `dist/assets/shots`).
Новый кадр кладём в двух размерах: `cf-<id>.webp` (1600 px) и `cf-<id>-s.webp`
(900 px); `npm run check` проверяет, что все кадры из `dist/js/config.js` есть на диске.

3D-сцены в проекте нет: модули сцены, модель, three и скрипты её сборки удалены.
Прежняя 3D-версия осталась только в истории git.

## Каталог услуг

Цены и тексты услуг живут в `dist/assets/meatwash-content.json`, а не в разметке.
После правки данных:

```
npm run catalog        # перегенерирует каталог в dist/index.html
npm run check
```

## Pull request

Шаблон подставится сам. Заполняем все разделы, включая «Чего в этой ветке нет» —
честно написанный недоделанный пункт экономит следующему человеку полдня.

Ревьюер назначается автоматически через `.github/CODEOWNERS`. К каждому запуску
проверок прикладывается собранная папка `dist` — её можно скачать из вкладки
Actions и открыть локально, не поднимая ветку у себя.

После слияния ветку удаляем.

## Чего не делаем

- Не пушим напрямую в `main`.
- Не правим ничего на живых сайтах клиента.
- Не кладём в репозиторий пароли, токены и доступы — ни в код, ни в комментарии,
  ни в описание pull request.
- Не коммитим `node_modules`: они уже в `.gitignore`.

## Кэш после выкладки

GitHub Pages разрешает браузеру держать файлы 10 минут. Чтобы новый HTML не
смешивался со старыми стилями, при публикации `pages.yml` запускает
`scripts/stamp-assets.mjs`: к адресам CSS и JS добавляется `?v=<коммит>`.
В репозитории адреса остаются без версии — руками ничего ставить не нужно.
